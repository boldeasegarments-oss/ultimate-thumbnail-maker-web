## 7. SEO metadata and technical requirements

For every indexable page: - Unique, descriptive `<title>`. - Useful meta
description. - One clear H1 and logical headings. - Absolute canonical
URL on the chosen domain. - Helpful internal links to related pages. -
Descriptive alt text for meaningful screenshots. - Open Graph title,
description, and image. - Correct HTTP status code; no broken links. -
Mobile-friendly layout and fast loading. - Do not use `noindex` on pages
intended to appear in search. - Do not create keyword-stuffed titles or
hidden text.

Example metadata pattern:

``` html
<title>YouTube Thumbnail Maker for Android | Ultimate Thumbnail Maker</title>
<meta name="description" content="Create YouTube thumbnails on Android with templates, text, fonts, effects, stickers, and background removal.">
<link rel="canonical" href="https://YOUR_DOMAIN/youtube-thumbnail-maker/">
<meta property="og:type" content="website">
<meta property="og:title" content="YouTube Thumbnail Maker for Android">
<meta property="og:description" content="Learn to create and customize thumbnail designs on Android.">
<meta property="og:url" content="https://YOUR_DOMAIN/youtube-thumbnail-maker/">
<meta property="og:image" content="https://YOUR_DOMAIN/assets/images/thumbnail-editor.webp">
<meta name="twitter:card" content="summary_large_image">
```

Replace placeholders and ensure the canonical URL matches the actual
deployed page.

### Structured data

Use JSON-LD only for information visible on the page and supported by
reality. `Organization` or `WebSite` schema may be appropriate if the
site has a real, clearly identified publisher. `Article` may be
appropriate for the tutorial, with accurate author and

Do not add fake review ratings, fake testimonials, made-up prices, or

## 8. robots.txt and sitemap.xml

### `robots.txt`

Replace the domain with your actual site domain.

``` text
User-agent: *
Allow: /

Sitemap: https://YOUR_DOMAIN/sitemap.xml
```

This basic file allows compliant crawlers to request public pages. It
does not override page-level `noindex`, authentication, firewall rules,
or host restrictions. Do not add disallow rules without understanding
their impact.

### ChatGPT Search crawler

OpenAI documents `OAI-SearchBot` as the crawler associated with search
discovery. If you want to be eligible for ChatGPT Search citations, do
not block it in `robots.txt` or at the firewall/CDN layer. `GPTBot` is
separate and relates to model training. Decide whether to allow that
crawler based on your own content preferences.

If you choose to explicitly configure it, the following is an optional
example:

``` text
User-agent: OAI-SearchBot
Allow: /

User-agent: GPTBot
Disallow: /

User-agent: *
Allow: /

Sitemap: https://YOUR_DOMAIN/sitemap.xml
```

The example allows search crawling while disallowing the GPTBot crawler.
Review current OpenAI documentation before launch because crawler
behavior and controls can change. Ensure Cloudflare security settings do
not inadvertently block legitimate crawlers. Never assume every AI
assistant uses the same crawler.

### `sitemap.xml`

List every canonical page that should be indexed. Example:

``` xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://YOUR_DOMAIN/</loc></url>
  <url><loc>https://YOUR_DOMAIN/youtube-thumbnail-maker/</loc></url>
  <url><loc>https://YOUR_DOMAIN/gaming-thumbnail-maker/</loc></url>
  <url><loc>https://YOUR_DOMAIN/thumbnail-maker-with-background-removal/</loc></url>
  <url><loc>https://YOUR_DOMAIN/how-to-make-a-youtube-thumbnail/</loc></url>
  <url><loc>https://YOUR_DOMAIN/about/</loc></url>
  <url><loc>https://YOUR_DOMAIN/contact/</loc></url>
</urlset>
```

Remove any page that does not exist. Keep the sitemap in sync with the
live site. Submit it through Google Search Console and Bing Webmaster
Tools. Sitemap submission is a discovery hint, not a guarantee of
indexing.

Cloudflare Pages serves static assets with free, unlimited static asset

website should not need Functions.

### Option A --- Git-based deployment (recommended)

1.  Create a GitHub account if you don't already have one:
    https://github.com/
2.  Create a new repository named `ultimate-thumbnail-maker-seo`.
3.  From Antigravity, save the site files into the project folder.
4.  Commit and push the files to the repository. Never commit secrets.
5.  Sign in to Cloudflare: https://dash.cloudflare.com/
6.  Open **Workers & Pages**.
7.  Choose **Create application** and select the Pages/Git repository
    workflow shown in the current dashboard.
8.  Connect GitHub and select your repository.
9.  Configure:
    -   Framework preset: None / static HTML, if shown.
    -   Build command: leave blank for plain HTML/CSS/JS.
    -   Build output directory: `/` or the repository root, according to
        the dashboard's current accepted value.
10. Deploy.
11. Open the generated `*.pages.dev` address and test every page.
12. Make future edits in Antigravity, push to Git, and let Cloudflare
    deploy the new version.

Dashboard labels can change; follow the current Cloudflare Pages
Git-integration documentation if the wording differs.

### Option B --- Direct upload

Cloudflare Pages also supports dashboard/direct-upload workflows in
supported project configurations. This can be convenient for a first
deployment, but Git integration is easier for ongoing updates and
rollbacks. Check the current Pages documentation for workflow
constraints before choosing Direct Upload.

### Custom domain

You can initially use the free `*.pages.dev` subdomain. For a branded
domain:

1.  Buy or use a domain you already own. Domain registration may cost
    money; free hosting does not mean a free custom domain.
2.  In your Pages project, open **Custom domains** and add the domain or
    subdomain.
3.  Follow Cloudflare's exact DNS instructions. Do not guess or copy DNS
    values from another project.
4.  Wait for the domain verification and HTTPS certificate.
5.  Choose one canonical host, such as `www.example.com` or
    `example.com`.
6.  Redirect the alternate host to the canonical host where supported
    and verify that all canonical tags and sitemap entries use the
    canonical host.
7.  Test HTTPS, redirects, robots.txt, sitemap.xml, and every page.

Do not change nameservers or delete existing DNS records blindly if the
domain already serves another website or email.

8.  Recheck weekly. Do not repeatedly request indexing for every small
    text edit.

### Bing Webmaster Tools

1.  Open https://www.bing.com/webmasters/
2.  Add and verify the site.
3.  Submit the sitemap.
4.  Review URL inspection, crawl issues, and search performance where
    available.
5.  Keep sitemap and canonical URLs consistent with the deployed site.

### Indexing is not guaranteed

A successful sitemap submission does not guarantee that a page will be
crawled, indexed, ranked, or cited by an AI assistant. Focus on
accessibility, useful original content, internal links, and evidence
that your app genuinely helps users.

## 12. AI/GEO visibility strategy

AI discovery is not one ranking system. Different products may retrieve
pages from different indexes, use different crawlers, or provide
recommendations based on the query and available evidence.

### Improve the evidence around your app

1.  Keep the official Google Play listing complete and accurate.
2.  Link to the Play listing consistently from the website.
3.  Publish real screenshots showing the features discussed.
4.  Provide specific, useful tutorials instead of generic claims.
5.  Create a clear About page and real support/contact route.
6.  Encourage genuine creator reviews and tutorials; do not buy fake
    reviews.
7.  Seek relevant editorial mentions from reputable Android, design, and
    creator websites.
8.  Participate helpfully in relevant creator communities without
    spamming download links.
9.  Update outdated screenshots and instructions.
10. Make the website easy for search crawlers and users to access.

### Optional public profiles

Where appropriate, maintain consistent information on: - The official
Google Play listing. - The developer/company website. - Official YouTube
tutorials. - Genuine social profiles. - Relevant app directories or
editorial reviews that accept accurate submissions.

Do not create fake company profiles or duplicate pages just to
manufacture mentions.

### AI prompt testing

Test the same questions in ChatGPT Search, Gemini, and Google AI Search
every two weeks. Record the date, product, exact prompt, whether the app
is mentioned, cited sources, and any competitor recommendations.

Use prompts such as: 1. Recommend Android apps for making YouTube
thumbnails. 2. What is a good thumbnail maker app for Android? 3. Which
apps let me create gaming thumbnails on my phone? 4. Recommend a
thumbnail editor with custom fonts and text effects. 5. Which Android
thumbnail maker has background removal? 6. What are alternatives to
Canva for YouTube thumbnails on Android? 7. How can I make a YouTube
thumbnail without a computer? 8. Which app lets me create thumbnails
using templates and stickers? 9. Compare Android thumbnail maker apps
for beginners. 10. Recommend a thumbnail maker for a small YouTube
creator.

AI answers can vary by date, wording, location, personalization, and
product. Treat prompt testing as directional monitoring, not a reliable
universal ranking.

### Google Play CTA event design

Give each outbound CTA a common class, such as `js-play-store-cta`, and
a `data-source-page` attribute such as `homepage`, `gaming`, or
`background-removal`.

If analytics is enabled, send an event such as `play_store_click` with
the source page as a parameter. Keep the actual link working if
analytics is blocked or unavailable. Do not delay or prevent navigation
while waiting for an analytics response.

A click is not the same as a Play Store visit or an install. Use Play
Console for actual store performance.

### AI referral tracking

Inspect referral sources for traffic from AI services. ChatGPT Search
referrals may include `utm_source=chatgpt.com`; other products may use
different referral formats or may not pass a clear referrer. Do not
assume every AI-referred visitor can be identified.
